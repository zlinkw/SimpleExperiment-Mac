# 刷新、等待与资源锁

- 调度周期沿用用户配置，最小值为 0.5 秒，可使用小数秒。任务结束事件立即检查调度；重复信号合并。
- 事件连接持续保留。需要主动查询时每 0.5 秒兜底，上一请求结束后才安排下一次。隐藏面板暂停面板查询，任务调度继续。
- Worker 连接失败后停止自动重连。点击“重新连接”恢复断开的 Worker 并补读状态；健康 Worker 保持连接。
- 控制请求连续 30 秒没有有效响应，文件步骤连续 120 秒没有真实进展，结束等待并传递取消。字节、文件数量和实际阶段推进可延长等待；心跳、转圈和重复状态不能延长。
- 等待用户确认时暂停业务计时。运行、关闭或删除的结果不明确时，保留“执行结果待确认”；恢复连接后先核对，避免重复修改。
- 哈希缓存依据文件身份、大小和修改元数据复用；没有仅按时间禁止刷新的规则。新增或修改文件重算，手动刷新立即检查变化。
- 两款插件采用同一资源锁协议。服务器与实际目标路径决定冲突，父目录和子路径互斥，不同目标及只读查询可并行。锁只覆盖修改阶段；停止与取消不等待校验。
- 每窗口一个原子更新的锁登记文件，短暂协调只用于登记与释放。业务期间持续续约；崩溃后依据持有证明与失效时间恢复。登记释放不删除文件。
- 同一 Plan 重复提交保护与队列写入串行保留。跨窗口写队列时读取最新磁盘内容，拒绝覆盖过期快照。
- 活跃旧版全局锁不能绕过。请重新加载持有窗口，使两款插件同时升级，再重试。
- GPU 占卡限制、文件位置确认和删除双重确认保留。

## 升级操作

重新加载 VS Code 窗口，然后在插件内部署最新版 Agent。若操作显示“执行结果待确认”，先点击“重新连接”，再点击“刷新运行状态”核对结果。

## 验证范围

使用本地模拟 HTTP 服务、事件流、提取函数和隔离文件验证刷新、进展、取消、连接恢复、资源冲突和队列并发。未通过真实插件接口启动研究实验或触发人工确认弹窗；真实 Worker 部署后的端到端验证由用户完成。
