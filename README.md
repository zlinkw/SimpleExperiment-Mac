# SimpleExperiment Mac

Apple Silicon、macOS 26+ 的 VS Code 扩展，配套 SimpleSFTP Mac 管理 Linux GPU 实验。扩展身份、设置和应用数据与 Windows 原版独立；业务以本版声明的 Windows 冻结实现为唯一来源。

**本配套 preview 版本为 Experiment 0.5.317、SFTP 0.2.104，参考冻结 Windows 0.5.416 / 0.2.114。** 发行附件与校验值以 [preview-v0.5.317](https://github.com/zlinkw/SimpleExperiment-Mac/releases/tag/preview-v0.5.317) 的实际清单为准。验收范围及 M5 真机边界见 [项目事实](docs/mac-project-facts.md)，冻结基线见 [源码对齐记录](docs/windows-alignment-2026-10-27.md)。

本轮同步 Windows 0.5.416 / 0.2.114 共同业务：多项目分支与创新分支（登记、worktree 创建、统一 GPU 配额派发、结果对比、HEAD 核对、科研 PR 与祖先快进）、暂存槽占用与用户确认提前释放、插件日志保留、操作完整日志入口和统一 CLI 命名动作。VSIX 内根 README 的上一版版本说明属于文档遗留，实际版本与校验值以本 Release 的 package/release 清单为准；最新说明以本仓库为准。

## 系统与安装

- Apple Silicon、macOS 26 及以上，配套使用 VS Code 1.100.0+；目标真机为 M5、24 GB、macOS 27.0，本次尚未执行真机验收。
- Linux Worker 使用 SSH、tar、Python、tmux 和用户配置的 Python/Conda 环境。
- Intel Mac、Dev Containers、PPT 自动绘图不在本轮范围；本轮没有验证这些入口。

发行包见 [SimpleExperiment Mac Releases](https://github.com/zlinkw/SimpleExperiment-Mac/releases)。两款 darwin-arm64 VSIX 和 release.json 位于同一个 preview Release；公开下载无需登录。首次在命令面板 **⇧⌘P → Extensions: Install from VSIX…** 依次安装 **SimpleSFTP Mac → SimpleExperiment Mac**，再 **Developer: Reload Window**。实际发行版本以对应 Release 为准。

## 配置与运行

1. **File → Open Folder…** 打开本机项目；一个窗口只打开一个项目。按 **⇧⌘P → SimpleExperiment：打开面板**，顶部 **配置说明** 打开 [Mac 配置说明](docs/simple-experiment-setup.md)。
2. 配置 SimpleSFTP Mac 的真实服务器、用户、SSH 端口和项目父目录。通过 **SimpleSFTP Mac：配置服务器认证** 选择密钥、ssh-agent、密码或系统 SSH 配置；默认仅会话内记忆，明确勾选后才使用 SecretStorage 保存。
3. 在 SimpleExperiment 的 **服务器** 配置启用 Worker，可配置一台或多台。保存服务器地址、用户、SSH 端口、项目父目录、Conda 环境、tmux 前缀以及本机/远端转发主机和端口。业务只使用明确启用的 Worker；Hub 已退役，旧记录不补出目标。
4. **SimpleExperiment：准备 Agent 并启动 / 部署Agent** 使用共同的受管流程，通过 SimpleSFTP 更新 Agent 和独立 Scheduler。核对目标并在对话框点击 **确认上传并查看指引** 完成确认；复用、更新、重启和失败恢复均沿用 Windows 实现。Mac 没有可编辑的会话文件，Agent 启动由共同受管生命周期协议保障。
5. 点击 **启动全部隧道** 经 macOS 系统 OpenSSH 一键启动全部已启用 Worker 的本地端口转发，认证复用 SimpleSFTP Mac 的独立认证，不读取 Termius 私有会话；旧 simpleExperimentMac.tunnel.manualEndpoints 设置保留读取兼容。Termius 手动指引作为备份保留；启动请求、真实隧道与 Agent 就绪分别报告，以实际检测为准，macOS 真机验收尚未执行。
6. 选择当前 PLAN 的完整路径，按共同界面执行校验、预演和提交。自动同步、静态入口探针、Worker 准备、覆盖确认、队列和显存调度均沿用 Windows；不会用另一 PLAN 代替当前选择。

GPU 会话只在置顶 GPU 卡片展示；选中后展开任务与终端，名称为日志入口。停止、关闭和保留会话的清空使用精确绑定。正式产物只保留最新版；每个 job 完成后的同步取该 job 最新产物与当前勾选范围的交集。操作失败后按实际查询重查，不用历史回执推断成功。

本版支持 **批量选择 PLAN → 运行所选计划**：只提交显式勾选项，逐个沿用单PLAN校验和覆盖确认；失败、取消或结果未知后停止后续项，空选择不会运行全部。任务卡分开展示执行、产物完整及日志复核状态，**重新分析运行日志**不会重跑；异常job使用 **覆盖产物并重跑此 job**，保留原有路径双确认。结果汇总主动读取当前声明和Worker实际产物，仅保存最新汇总JSON及CSV/Markdown。

Worker按各自请求独立刷新，慢节点不阻塞其他节点；pending不等于失败。产物复制不再全局阻止PLAN提交，真实重叠路径仍保护。清理保留PLAN及共享配置，Worker重连不重复弹历史清理提醒。这些流程已完成隔离回归，Mac真机尚未验证。

同时包含每卡 job 配额/剩余显存门槛、显式派发剩余任务、源码范围校验、自动文件索引/内容比较、批量隔离删除和混合版本结果归属。Termius、Mac独立认证/preview源与原生句柄证明保留。同步范围本机删除已接入Darwin整树冻结和句柄证明，隔离替身通过13项；证明不完整时继续阻断。**真机libproc、权限及实际删除均未验证，不能视为功能全部对齐。**

## 多项目分支与工作树

同一个科研仓库常常要并行验证多个想法。这个功能把“一个祖先仓库 + 若干创新分支副本”登记在同一台机器上，让它们各跑各的实验、共用一套 GPU 配额判定，最后只把选中的分支经 PR 合回祖先。入口在面板“实验准备”下方的“项目与分支”卡片。

### 两个概念

| 名称 | 含义 |
| --- | --- |
| 祖先项目 | 本机已有的仓库根（科研主线）。「登记」这一步只往本机登记表写目录、目标分支和 remote，不修改仓库里的任何文件；后面经你单独确认的「创建分支」会在祖先仓库里新建分支和 worktree 目录，PR 合并后的「祖先快进」会更新祖先的工作树。 |
| 创新分支 | 该祖先的另一个独立工作目录（`git worktree` 或独立 clone），有自己的分支、任务队列和产物目录。 |

登记表是本机唯一一份 `~/Library/Application Support/SimpleExperimentMac/branch-projects.json`，所有 VS Code 窗口共用。同一目录只能登记一次；登记表损坏时插件拒绝继续读写，也不会覆盖它。

### 登记与创建分支

1. 点 **登记祖先项目**，选择含 `.git` 的仓库根。弹窗列出目录、当前分支、HEAD 和有没有未提交修改，确认后才写入登记。非 Git 仓库、`detached HEAD` 或读不到 Git 状态会被拒绝。
2. 创新分支有两条路：
   - **从祖先创建分支**：填分支名：必须以英文字母或数字开头，其余字符只能是字母、数字与 `. _ - /`，不能含 `..` 或 `//`，不能以 `/` 结尾；再选存放父目录。预览列出祖先目录、新分支、基点提交、将要新建的目录（必须尚不存在）以及将执行的 `git worktree add <新目录> -b <新分支> <基点>`。确认后才创建；同名分支或已存在目录一律拒绝，不覆盖。祖先当前有未提交修改时，新分支只从已提交的基点创建，不会把未提交内容带过去。
   - **登记分支副本**：已经自己用 `git worktree` 或 `clone` 建好的目录，选择所属祖先和目录后确认，只登记归属，不合并、不移动提交。
3. **刷新状态** 只读重读每个登记的真实 Git 状态：已验证、目录缺失、不是Git仓库、身份漂移（实际 Git 根或分支与登记不符）、有未提交修改、detached HEAD、读取失败。分支还显示与祖先的关系：与祖先同点、领先祖先、已分叉、独立仓库（关系未证明）、关系未知。科研验证不在这里自动执行，需要在该分支窗口自己跑计划和门禁。
4. 每行的 **打开** 在新窗口打开该项目（独立实例），当前窗口的工作区不变；当前窗口已经是该项目时只提示，不重复开。
5. **移除登记** 只删除插件内的登记记录，不删目录、分支、worktree 或提交，之后可以重新登记。祖先下面还有分支登记时会先拒绝，需要你逐个移除分支登记后再移除祖先。

### 多分支并行运行

- **刷新统一策略**：把当前窗口的 GPU 配额设置（每卡任务数、最低空闲显存、并发卡上限）保存为本机统一策略快照。预览逐台列出“新增 / 更新 / 保持 / 保留”，只替换本窗口核实过的服务器，其它窗口登记且冲突的条目保留原值。登记或移除项目后插件会自动补一次快照，失败只写进操作日志，不会吞掉登记结果。
- 统一区块逐个已登记项目显示 **待派发 / 运行中 / 待核实** 和阻塞原因，并标记 **已打开(握手确认)** 或 **未确认打开**。是否打开只认实时握手，遗留的旧实例记录不算打开。
- 每行的 **提交运行**：选择该分支项目里的 PLAN，由该分支窗口自己判定能否直接提交；确认后任务进入该项目自己的持久队列，产物冲突等确认仍在该分支窗口弹出。当前窗口不代为准备环境，也不做任何 Git 写操作。目标必须是已登记项目根，插件不按面板传来的路径猜测；分支窗口未打开或不可达时直接拒绝并说明原因。
- 并行只在既有 GPU 配额允许时发生。配额已满时该任务本轮不发送，也不会挤掉已经在占卡的作业；它带着“统一派发等待配额”的原因留在原队列，后续调度可以用同一个命令身份重新申请名额。只有“提交结果未知”时才绝不自动重发，以免重复提交。
- **刷新运行状态**：逐个已登记项目做真实握手并拉取最近操作记录；没刷新过的一律不猜。
- 统一派发只在“已登记项目不少于两个、且当前窗口自身也在登记内”时生效；只有一个项目时仍走原来的单项目流程。

### 结果对比与 HEAD 核对

- **结果对比与选优** 读取本机各登记项目的队列记录，逐个 PLAN 显示计划文件名、已确证作业数／作业总数、运行中、待核实、等待（有失败或中止时一并显示），以及该 PLAN 的运行来源分支与提交（当时有未提交修改、或当时脏状态未知时会标注，干净时不标注）和有没有已验源码清单。它只列事实，不替你做科研优劣判断。
- **核对HEAD** 只读地把当前提交树中“已验源码清单”覆盖到的文件逐个比对字节（类型、大小、内容 SHA），并同时显示该 PLAN 的运行来源提交，与当前 HEAD 不同会明确标出。它只证明清单内的源码与配置跟已验字节一致：不覆盖整仓，不含数据、权重和仓外输入，不证明这批结果的实际运行就出自当前 HEAD，也不代表科研运行已完成或科研结论等价。清单里没有的依赖（被 Git 忽略或未跟踪的文件）算无法证明，插件不会代为提交来凑证明。

### 科研 PR 与祖先快进

推送与合并是两步，各自需要单独确认：

1. **创建PR** 前需要在该项目里选定一个或多个 PLAN（可多选，插件不自动判优），并满足：该 PLAN 的作业全部完成确证、当前 HEAD 逐文件等于已验清单、工作树干净。预览显示合并目标（登记祖先的真实 origin，凭证已剥离）、目标分支、来源分支与完整提交、既有 PR 状态以及相对基线的领先/落后。推送只允许普通快推，不 force；确认后每次真正写入前还会重读队列和身份重跑同一校验，撤证、版本或命令变化立即零写入停止。`gh` 未安装或未登录时如实失败，插件不代装代登。
2. **合并PR** 只在存在“远端头等于本机 HEAD”的开放 PR 时执行，并使用 `--merge` 加 match-head 约束；远端头一旦变化 GitHub 会拒绝，不会盲合，也不使用管理员权限。合并同样是不可逆的远端写入：需要你重新选择 PLAN，并重新满足同一候选门禁（该 PLAN 作业全部完成确证、HEAD 逐文件等于已验清单、工作树干净），确认后、真正发送前还会再复核一次，撤证或版本变化就零发送。结果未知时绝不重放，再次点击只做只读对账；PR 已经在网页被合并的走只读恢复，核对通过后才取真实合并提交，不重发合并指令。
3. 确认真实合并之后，才会经你**再次单独确认**尝试更新本机祖先：祖先必须干净、正处在目标分支、真实 origin 仍与登记时的祖先地址一致、远端确实包含该合并提交、且本机 HEAD 是该远端目标的祖先，才 `ff-only` 快进，不产生合并提交；任一条件不满足都会明确说明“未更新”。合并后主线仍需按流程重新验证，之前的候选验证不自动等于主线已验证。

### 边界

- 不 reset、rebase、stash、强推、删除，也不代为 stage/commit。
- 不修改你的 Git 配置和 `.gitignore`。`simple_cluster/state/` 产生的未提交记录由你按仓库自身规则排除，插件不会把整个 `simple_cluster/` 忽略掉。
- 登记、创建分支 worktree、移除登记与派发同意都走同一项本机共享资源，避免两个窗口同时改登记或同时发卡。

### 常见提示

| 提示 | 怎么处理 |
| --- | --- |
| 该分支项目未打开或实例不可达 | 先在卡片上点 **打开** 打开该分支窗口，再重试提交或刷新。 |
| 工作区 …… 实际存在 N 个存活实例 | 同一项目被多个窗口打开。面板操作请关掉多余窗口后重试，面板提交不能指定实例；使用命令行时可以把错误信息里给出的完整 `--instance <pid:startedAt>` 传给该命令。 |
| 目录 X 已登记为 Y；同一目录不能重复登记 | 先移除旧登记，或换另一个目录。 |
| branch-projects.json 内容损坏 | 不要手工覆盖该文件；先人工核对内容再处理，在此之前插件不写登记。 |
| 服务器 X 的配额策略与当前配置已变化 | 点 **刷新统一策略** 重新登记快照。 |

## 验收与真机边界

已完成两仓本地构建、类型检查、生成面板脚本、逐文件串行隔离回归、真实 Chromium 主题验证及 Windows 专属回归；收包、VSIX 完整性和公开更新入口按配套发布流程核对。未连接生产服务器、部署远端 Agent、安装开发机扩展、停止远端任务或处理真实产物。M5认证、路径、隧道、单多Worker、macOS libproc、权限及实际删除仍未实机验证，不声称 Mac 系统体验完全一致。Mac原生句柄证明已接入SFTP检查分支及本机缓存执行器；发现占用返回ACTIVE_HANDLE，权限不足、ABI不符、查询变化或超时仍返回HANDLE_CHECK_UNAVAILABLE，无法取得完整句柄证明时继续阻断。
